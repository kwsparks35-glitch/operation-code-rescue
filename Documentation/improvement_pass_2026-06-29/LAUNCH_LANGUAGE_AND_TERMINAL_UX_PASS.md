# Launch Language And Terminal UX Pass - 2026-06-29

## Purpose

This pass completes the immediate start-screen language-selection priority and carries that choice
into the first coding surface the player sees in-game. The June 25 recommendations identify the HUD
and terminal as the next UX rollout targets after the shared `CodeRescueUITheme`; this pass focuses
on the terminal because it is where language lock, compiler availability, hints, validation, and
save confidence all meet.

## Implemented

- Confirmed the Xcode Metal Toolchain is available again with `xcodebuild -find metal`.
- Rebuilt the packaged Mac app successfully after the previous package attempt failed while invoking
  `metal`; the packaged app is at `PackagedMac/Mac/CodeRescueUnreal.app`.
- Verified the packaged launch menu visually with `Run_Launch_Menu_Visual_Check.command`; the
  screenshot check passed and the log scan reported only the allowed CoreAudio sample-rate warning.
- Verified packaged startup with `Smoke_Test_Packaged_App.command null`; runtime log contracts
  passed while the active-play bypass loaded the selected default track.
- Extended `CodeTerminalWidget` onto the shared UI theme:
  - terminal text, buttons, code editor, output, and status banners now use semantic tokens from
    `CodeRescueUITheme`;
  - the code editor uses a monospace style with terminal-green foreground;
  - validation output now turns terminal-green on success and danger-red for repair-needed states;
  - the hint button now says `Ctrl+H`, matching the implemented keyboard shortcut.
- Added a visible terminal language-save contract:
  - `LOCKED TRACK: <language>`;
  - the exact language save profile generated by `UCodeRescueGameInstance::MakeLanguageSaveSlotName`;
  - copy stating that progress, hints, attempts, and solves remain in this language and can be
    resumed from the start screen next launch.
- Added `Scripts/verify_terminal_language_track_ux_pass.py` and wired it into both
  `Run_Full_QA_Audit.command` and `Run_Local_CI_Readiness.command`.
